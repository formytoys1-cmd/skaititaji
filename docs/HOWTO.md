## 3. Мобильное приложение

### 3.1 Установить как приложение (PWA) — бесплатно, без магазинов
- **iPhone (Safari):** открыть сайт → «Поделиться» → «На экран Домой».
- **Android (Chrome):** появится кнопка «Установить приложение» (или меню →
  «Установить»).
- Приложение работает офлайн (страница «Нет соединения»), с иконкой и splash.

### 3.2 QR-коды для передачи
- Страница с QR: https://skaititaji.onrender.com/koplietosana

- Кнопки: «Копировать ссылку», «Скачать QR», «Печать».

### 3.3 Нативное приложение (App Store / Google Play)
- Каркас в папке `mobile/` (Expo/React Native, WebView-обёртка).
- Публикация: см. `mobile/README.md` (Apple $99/год, Google $25, EAS Build).

## 4. Консоль обратной связи (как заказать правку/сообщить баг)

1. Войти как `admin@demo.lv` → открыть **/admin/inbox**.
2. Создать «Новое указание»: заголовок, тип, приоритет, описание; можно
   прикрепить файлы (скриншоты, бумажные формы).
3. Отправить. Ответы агента приходят **в тот же тред автоматически** (без
   перезагрузки). Новые сообщения — сверху, значок «Новый ответ агента».
4. Язык интерфейса переключается кнопками LV / RU / EN вверху.

## 5. Автономная разработка: форк-агент + авто-мердж

### 5.1 Как это устроено
- **main-чат** — основная сессия (вы + агент). Ветка `main`.
- **Форк-агент** — автономный агент на ветке `agent/console` в отдельном
  git worktree. Слушает консоль и вносит правки **независимо**, не занимая
  основную сессию.
- **Прод (Render) деплоится только из `main`.** Значит правки форка попадают
  в прод только после мерджа — это защита.

### 5.2 Авто-мердж (безопасный, с проверками)
Слияние `agent/console → main` делает GitHub Actions с обязательными гейтами:
- приложение поднимается (`import app.main`);
- доступность **WCAG 2.2 AA** (axe);
- **PWA smoke** (манифест/service worker/офлайн/иконки — устанавливаемость).

Мердж происходит **только если все гейты зелёные**. Конфликты не заливаются.

### 5.3 Когда происходит мердж
| Триггер | Периодичность / как |
|---------|---------------------|
| **По расписанию (автономно)** | **каждые 6 часов** — сам, без запроса. Если ветка не опережает main, запуск быстро пропускается (не грузит CI). |
| Команда из консоли | напишите в консоли `[merge]` (или `[merge agent/console]`) — мост раз в 10 мин запустит мердж и ответит в тред. |
| Вручную (вы) | GitHub → Actions → workflow **automerge** → Run workflow. |
| Форк-агент | сам после своих проверок. |

> Итог: **ничего специально запрашивать не нужно** — накопленные правки форка
> сольются в прод сами, максимум в течение ~6 часов, при зелёных проверках.

### 5.4 Локальные команды (для разработчика)
```bash
# worktree форк-агента
git worktree add ../skaititaji-console-agent agent/console

# ручной безопасный мердж с пушем
GH_PUSH_TOKEN=<token> python -m tools.automerge agent/console --push

# PWA smoke локально
python tools/audit/pwa_check.py http://127.0.0.1:8000

# a11y-гейт локально (нужен запущенный сервер)
cd tools/audit && BASE_URL=http://127.0.0.1:8000 node a11y.mjs
```

## 8. Частые вопросы

**Как быстро мои правки из консоли попадут на сайт?**
Форк-агент реализует их на своей ветке, а авто-мердж по расписанию (каждые
6 часов) сольёт в прод при зелёных проверках. Нужно быстрее — напишите в
консоли `[merge]`.

**Что если проверка (a11y/PWA) упадёт?**
Мердж не произойдёт — прод не пострадает. Правку нужно поправить на ветке.

**Занимает ли консоль основную сессию?**
Нет. Консоль обрабатывает форк-агент в отдельной ветке/контексте; основная
сессия остаётся свободной.

**Как поделиться доступом с жителями?**
Дайте QR со страницы `/koplietosana` (или распечатайте листовку кнопкой
«Печать»).

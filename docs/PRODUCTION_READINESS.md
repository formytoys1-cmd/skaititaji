# Готовность к продакшену + план по моделям · Skaitītāji

> Оценка на 2026-08-20. Проект — мультиарендная SaaS для подачи показаний
> счётчиков воды (FastAPI + Jinja/PWA + Expo, интеграция Visma Horizon).
> Состояние: рабочий MVP (~5 600 строк Python, 50 коммитов), демо-режим.

---

## 1. Что уже готово (MVP)

- **Бэкенд FastAPI**: auth, модели (SQLModel), роутеры (resident, manager,
  moderator, admin, public, pwa, share, agent_api, management).
- **Мультиарендность** + config-driven типы счётчиков.
- **Подача воды ХВС/ГВС**: карточки, предыдущее показание, live-расчёт, валидация,
  детекция аномалий.
- **Кабинет управляющего**: прогресс, аномалии, CSV-экспорт.
- **Интеграция Visma Horizon**: клиент написан, коды REST-сервисов заведены —
  но работает в **mock-режиме** (`VISMA_MOCK=1`).
- **PWA**: manifest, service worker, offline, устанавливаемое приложение.
- **Мобильное**: каркас Expo/React Native (iOS + Android).
- **i18n** RU/EN/LV, деплой Docker + Render/App Engine, форк-агент с авто-мерджем.

## 2. Что осталось доделать до продакшена (gap-анализ)

### 🔴 Блокеры (без этого в прод нельзя)

| # | Пробел | Где | Риск |
|---|---|---|---|
| B1 | **Нет тестов** (0 test-файлов) | весь проект | регрессии, нельзя безопасно рефакторить |
| B2 | **Visma Horizon только mock** — не проверено на реальном API (Basic auth, NĪP/KNS, sync/new) | `app/integrations/visma_horizon.py` | ядро ценности не подтверждено |
| B3 | **SECRET_KEY по умолчанию** `dev-secret-change-me`, `DEBUG=1` по умолчанию | `app/config.py` | подделка сессий, утечки в проде |
| B4 | **Аутентификация — демо** (email+пароль). ТЗ требует банк / Smart-ID / eParaksts (eIDAS) | `app/auth.py` | несоответствие латвийскому рынку |
| B5 | **SQLite по умолчанию** — не для многоарендной нагрузки | `app/config.py` | конкуренция записи, потеря данных |

### 🟠 Важное (нужно до реальных пользователей)

| # | Пробел | Комментарий |
|---|---|---|
| I1 | Нет CSRF-защиты на POST-формах | SameSite=Lax частично помогает, но не для форм |
| I2 | Нет rate-limiting / защиты от brute-force на логине | важно для публичного портала |
| I3 | Миграции БД (Alembic) отсутствуют | схема меняется — нужен контролируемый апгрейд |
| I4 | GDPR: политика хранения, экспорт/удаление перс. данных жильцов | требование ЛР/ЕС |
| I5 | Логирование/аудит действий (кто подал/изменил показание) | споры по расходу воды |
| I6 | Обработка ошибок Visma (ретраи, таймауты, идемпотентность записи) | сеть on-premise ненадёжна |

### 🟡 Желательное (после запуска)

- Мониторинг/алерты (Sentry), health-дашборд арендаторов.

## 3. Рекомендуемый порядок работ

1. **B3** (секреты/DEBUG) — 30 минут, критично и дёшево.
2. **B1** (тестовый каркас pytest + httpx) — фундамент для всего остального.
3. **B2 + I6** (реальный Visma: sandbox-прогон, ретраи, идемпотентность).
4. **B5 + I3** (Postgres + Alembic-миграции).
5. **I1, I2** (CSRF + rate-limit).
6. **B4** (Smart-ID / eParaksts) — крупная веха, планировать отдельно.
7. **I4, I5** (GDPR + аудит).

## 4. Какая модель под какую задачу (экономия без потери качества)

Профиль проекта — **инженерия ПО (full-stack)**. Правило: **Sonnet — рабочая
лошадка**, **Opus 4.8 — точечно на «трудные узлы»**, режим **«Высокая 1M»** —
когда нужно держать в контексте весь стек.

| Задача | Модель | Почему |
|---|---|---|
| **B2** Реальная интеграция Visma (контракты API, sync, идемпотентность) | **Opus 4.8** | цена ошибки высока, сложные внешние контракты |
| **B4** Smart-ID / eParaksts / eIDAS-аутентификация | **Opus 4.8** | безопасность + незнакомый протокол |
| **B3** Секреты/DEBUG/конфиг прода | **Sonnet** | простые точечные правки |
| **B1** Каркас pytest + первые тесты роутеров/сервисов | **Sonnet** | типовой код, много объёма |
| **B5+I3** Postgres + Alembic-миграции | **Sonnet** (архитектурное решение — **Opus 4.8**) | миграции рутинны, стратегия — reasoning |
| **I1 CSRF, I2 rate-limit** | **Opus 4.8** (дизайн) → **Sonnet** (реализация) | безопасность требует точности |
| **I5** Аудит-логирование | **Sonnet** | стандартный паттерн |
| **I4** GDPR (право ЛР/ЕС) | **Opus 4.8** | юридический reasoning, как в ds-riga |
| Фичи UI: шаблоны, PWA, i18n, кабинет, CSV | **Sonnet** | быстро и дёшево |
| Мелочи: CSS/HTML, тексты, README, конфиги | **лёгкая (Sonnet/Haiku)** | reasoning не нужен |
| Большой рефакторинг через весь стек (модель→сервис→роутер→шаблон) | **Opus 4.8 + «Высокая 1M»** | нужен весь контекст сразу |
| Разбор сквозного бага по всему стеку | **Opus 4.8 + «Высокая 1M»** | глубокий анализ |

### Правило большого пальца
- **Opus 4.8** → безопасность, auth, реальные внешние API, право/GDPR, архитектура,
  сложная сквозная отладка.
- **Sonnet** → фичи, шаблоны, тесты, CRUD, миграции, i18n — 70–80% ежедневной работы.
- **«Высокая 1M»** → включать, когда задача охватывает много файлов сразу.

> Сравнение с соседним проектом **ds-riga**: там профиль — анализ данных + право +
> новые решения, поэтому **Opus 4.8 оправдан почти всегда**. Здесь профиль —
> стандартная веб-разработка, поэтому **по умолчанию Sonnet**, а Opus 4.8 — точечно.
